Two-Mac AWDL Test

Proving Minecraft traffic can cross Apple peer-to-peer Wi-Fi with no router. ~10 minutes.

What this decides

The relay already works end to end on one machine. What it cannot prove is that bytes actually travel over AWDL (Apple's peer-to-peer radio) rather than looping back locally. Two Macs with Wi-Fi switched off is the only way to know. The transfer is timed, and that number decides whether joining a world feels instant.

Setup

  1. Build on this Mac (call it Mac A): cd helper && swift build -c release
  2. Copy helper/.build/release/mcdirect-helper to Mac B by AirDrop or USB stick, since the network is about to go away.
  3. On Mac B: chmod +x mcdirect-helper
  4. Turn Wi-Fi OFF on both Macs. Leave Bluetooth ON, since macOS uses it to bootstrap AWDL.

If macOS blocks the binary on first run, right-click it in Finder and choose Open, or run xattr -d com.apple.quarantine mcdirect-helper. It is ad-hoc signed, not notarised.

Run it

Mac A

Stands in for the Minecraft server. Start this first.

pkill -f 'nc -l 19999'
nc -l 19999 > /tmp/got.bin &
sleep 300 | ./mcdirect-helper \
  host --port 19999 \
  --name "TestWorld" --code 1234

The pkill matters: a leftover listener from an earlier attempt keeps port 19999 and swallows the transfer, so you get a passing tunnel and an empty file. Check the result afterwards with ls -l /tmp/got.bin.

Wait for {"event":"ready"...} before moving to Mac B.

Mac B

Discovers Mac A and opens the tunnel.

sleep 300 | ./mcdirect-helper browse --auto | tee /tmp/browse.log

Watch for "event":"found" then "event":"connected". Then in a second terminal. This picks the localPort out of the log for you, nothing to substitute: 

PORT=$(grep -o '"localPort":[0-9]*' /tmp/browse.log 2>/dev/null | head -1 | cut -d: -f2)
if [ -z "$PORT" ]; then
  echo "no tunnel yet: /tmp/browse.log has no localPort."
  echo "Run this on Mac B, in a second terminal, after 'connected' appears."
else
  time head -c 50000000 /dev/urandom | nc 127.0.0.1 "$PORT"
fi

Reading the result

Success is 50,000,000 bytes arriving on Mac A while both machines have Wi-Fi off. That alone proves AWDL carried it. The time output is the number that matters:

ElapsedThroughputVerdict
under ~10s> 5 MB/sJoining a world will feel instant. Ship it.
~10–50s1–5 MB/sWorkable. Initial chunk sync noticeable but fine.
over ~50s< 1 MB/sProblem. Likely stuck below realtime-mode elevation.

If it doesn't work

Nothing found on Mac B. Check System Settings → Privacy & Security → Local Network and make sure Terminal is allowed. This grant cannot be reset with tccutil, so a denial sticks. Confirm Bluetooth is on for both machines and they are within a few metres.

Found but never connected. AWDL took too long to bring the link up. Re-run Mac B; the first association is often the slow one.

Connected but zero bytes. Capture stderr on both sides (2> trace.log). The helper traces every connection state transition.
