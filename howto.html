Two-Mac AWDL Test

Proving Minecraft traffic can cross Apple peer-to-peer Wi-Fi with no router. ~10 minutes.

What this decides

The relay already works end to end on one machine. What it cannot prove is that bytes actually travel over AWDL (Apple's peer-to-peer radio) rather than looping back locally. Two Macs with no network between them is the only way to know. The transfer is timed, and that number decides whether joining a world feels instant.

Disconnect from Wi-Fi; do not switch it off. AWDL is a virtual interface on the Wi-Fi radio, so powering the radio down takes AWDL with it, which is why AirDrop needs Wi-Fi on as well. What this test needs is the absence of a shared network, not a dead radio.

Setup

  1. Build on this Mac (call it Mac A): cd helper && swift build -c release
  2. AirDrop both helper/.build/release/awdl-lan-helper and helper/twomac.sh into one folder on Mac B, before the network goes away.
  3. On Mac B: chmod +x awdl-lan-helper twomac.sh
  4. Leave Wi-Fi ON on both Macs, joined to no network. Open the Wi-Fi menu and disconnect, rather than switching Wi-Fi off. Leave Bluetooth ON, since macOS uses it to bootstrap AWDL.

If macOS blocks the binary on first run, right-click it in Finder and choose Open, or run xattr -d com.apple.quarantine awdl-lan-helper. It is ad-hoc signed, not notarised.

Run it

Mac A

Stands in for the Minecraft server. Start this first.

./twomac.sh host

It clears any listener left over from an earlier attempt, starts one on port 19999, and advertises over AWDL. Wait for advertising TestWorld, then leave it running: it reports bytes as they land.

Mac B

Discovers Mac A, opens the tunnel, pushes 50 MB, times it.

./twomac.sh join

One terminal, no port to copy across. It waits up to 60 seconds for discovery, then prints throughput and a verdict. For a fast smoke test first: MB=5 ./twomac.sh join.

Reading the result

Success is 50,000,000 bytes arriving on Mac A while both machines are on no network. That alone proves AWDL carried it. Mac B prints the verdict itself, so the table below is just what it is deciding between:

ElapsedThroughputVerdict
under ~10s> 5 MB/sJoining a world will feel instant. Ship it.
~10–50s1–5 MB/sWorkable. Initial chunk sync noticeable but fine.
over ~50s< 1 MB/sProblem. Likely stuck below realtime-mode elevation.

If it doesn't work

Either script prints the likely cause and dumps the helper log on failure, so start there.

Nothing found on Mac B. Check System Settings → Privacy & Security → Local Network and make sure Terminal is allowed. This grant cannot be reset with tccutil, so a denial sticks. Confirm Bluetooth is on for both machines and they are within a few metres.

Found but never connected. AWDL took too long to bring the link up. Re-run Mac B; the first association is often the slow one.

Connected but zero bytes. Capture stderr on both sides (2> trace.log). The helper traces every connection state transition.

Report back

Three things: did it transfer with neither Mac on a network, the MB/s line from Mac B, and the byte count from Mac A.
